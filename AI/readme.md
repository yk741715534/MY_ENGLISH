给我几份优质的 grilling 格式，以及 Next suggestion 格式

下面分两块：**Grilling 确认块（4 套风格，全部兼容你现有的 Agent Profile，可直接替换进所有 .agent.md）** + **Next suggestion / 调度建议（3 套变体）**。
核心原则：保持一套统一交互语法，用户只需要记住 `【全部同意】`，降低认知成本；同时区分「极简版」「详细评审版」「多方案对比版」「风险决策版」，适配不同决策权重。

> 统一约定：
>
>
> - 所有块用 ``` 包裹，方便一键复制
> - 保留 `建议回答`；用户可以【全部同意】或者手写覆盖
> - 不破坏你原有 AGENT-PROFILE-SPEC

## 一、Grilling 格式集合

### 格式 1｜标准默认版（推荐作为所有 Agent 默认，就是前面在用的，最稳）

适用：普通需求确认、字段确认、规则确认、范围确认

```
【{角色名}待确认】
待确认事项列表：
1. 事项描述
   建议回答：选项A / 选项B
2. 事项描述
   建议回答：选项A / 选项B
用户操作指引：
- 回复【全部同意】：采纳全部建议
- 回复自定义内容：覆盖/补充本次决策
```

示例填充：

```
【产品经理待确认】
待确认事项列表：
1. 客户数据权限规则
   建议回答：销售只能查看、编辑自己录入的客户；管理员可见全部客户
2. 跟进记录是否支持附件上传
   建议回答：暂不支持附件，仅文本跟进记录
用户操作指引：
- 回复【全部同意】：采纳全部建议
- 回复自定义内容：覆盖/补充本次决策
```

# Matt Pocock 原版 Grilling 两套格式（来自他官方 `grilling` / `grill-me` skill）

>
> 关键点区分：
>
>
> 1. `grill-me`：**一次一问**（串行，设计树深度优先，解决完一个依赖再下一个），最早原版
> 2. `grilling`（后续迭代版）：**一轮多问（frontier 前沿批次）**，同一批只放「前置依赖都已经解决」的决策点，一轮可以多条，等用户本轮全部回答后，再计算下一批前沿问题
>
>
> 我前面给的全部是一次性批量列表，**不是 Matt 原版范式**，这就是差异。
> 核心规则（必须写入 AGENT-PROFILE-SPEC）：
>
>
> - 问题按**设计决策树**组织；存在依赖关系的问题不能放在同一轮
> - 每个问题附带推荐答案；用户回复 `yes` 直接采纳推荐
> - 凡是代码 / 资产池里已经能查到事实的，不要问用户，自己读
> - 没有达成共识前，禁止推进产出主资产

> 设计思路：基于**决策树 + 前沿问题集**，存在依赖的问题不能同批次抛出；已在资产池有确定结论的事项，绝不重复问询。
> 保留快捷回复语义，和你现有体系兼容：`yes` 等价于【全部同意】。
