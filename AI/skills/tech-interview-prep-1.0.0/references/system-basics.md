# 计算机基础八股文

## 计算机网络

### TCP vs UDP

| 特性 | TCP | UDP |
|------|-----|-----|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠传输 | 不可靠 |
| 顺序 | 有序 | 无序 |
| 速度 | 较慢 | 较快 |
| 应用 | HTTP、FTP | DNS、视频流 |

### TCP 三次握手

```
客户端          服务端
  |  ---- SYN ---->  |  (1) 请求建立连接
  |  <-- SYN+ACK --- |  (2) 确认并同意
  |  ---- ACK ---->  |  (3) 确认服务端 SYN
```

**为什么是三次？**
- 防止已失效的连接请求突然到达服务端，造成资源浪费
- 两次握手服务端无法确认客户端是否收到了自己的确认

### TCP 四次挥手

```
客户端          服务端
  |  ---- FIN ---->  |  (1) 客户端请求关闭
  |  <-- ACK -----  |  (2) 服务端确认
  |  <-- FIN -----  |  (3) 服务端请求关闭
  |  ---- ACK ---->  |  (4) 客户端确认
```

**为什么是四次？**
- TCP 是全双工，每个方向的关闭都需要单独确认
- 服务端收到 FIN 后可能还有数据要发送

### HTTP 状态码

| 代码 | 含义 | 示例 |
|------|------|------|
| 200 | 成功 | OK |
| 301 | 永久重定向 | 域名更换 |
| 302 | 临时重定向 | 登录跳转 |
| 304 | 未修改 | 缓存命中 |
| 400 | 客户端错误 | 参数错误 |
| 401 | 未授权 | 需登录 |
| 403 | 禁止访问 | 无权限 |
| 404 | 未找到 | 资源不存在 |
| 500 | 服务器错误 | 代码异常 |
| 502 | 网关错误 | 上游服务不可用 |
| 503 | 服务不可用 | 过载维护 |

### HTTP vs HTTPS

| 特性 | HTTP | HTTPS |
|------|------|-------|
| 端口 | 80 | 443 |
| 安全 | 明文传输 | SSL/TLS 加密 |
| 证书 | 不需要 | 需要 CA 证书 |
| 性能 | 较快 | 略慢（握手开销）|

### GET vs POST

| 特性 | GET | POST |
|------|-----|------|
| 参数位置 | URL | 请求体 |
| 参数长度 | 有限制 | 无限制 |
| 安全性 | 较低 | 较高 |
| 缓存 | 可缓存 | 不可缓存 |
| 幂等性 | 幂等 | 非幂等 |
| 用途 | 获取数据 | 提交数据 |

### 浏览器输入 URL 发生了什么

1. **DNS 解析**：域名 → IP 地址
2. **TCP 连接**：三次握手
3. **发送 HTTP 请求**
4. **服务器处理请求**
5. **返回响应**
6. **浏览器解析渲染**
   - 解析 HTML 构建 DOM 树
   - 解析 CSS 构建 CSSOM
   - 合并生成渲染树
   - 布局计算
   - 绘制
7. **TCP 断开**：四次挥手

## 操作系统

### 进程 vs 线程

| 特性 | 进程 | 线程 |
|------|------|------|
| 资源 | 独立地址空间 | 共享进程资源 |
| 开销 | 创建切换开销大 | 开销小 |
| 通信 | 需 IPC 机制 | 直接读写共享变量 |
| 崩溃影响 | 独立 | 一个线程崩溃可能影响整个进程 |

### 进程通信方式 IPC

1. **管道 Pipe**：父子进程间单向通信
2. **命名管道 FIFO**：无亲缘关系进程间通信
3. **消息队列**：消息链表，按类型读取
4. **共享内存**：最快，直接读写
5. **信号量**：同步互斥，配合共享内存
6. **Socket**：跨机器通信

### 死锁

**四个必要条件**：
1. 互斥条件
2. 请求与保持条件
3. 不可剥夺条件
4. 循环等待条件

**预防策略**：
- 打破任一条件
- 资源有序分配（打破循环等待）

### 页面置换算法

| 算法 | 思路 |
|------|------|
| OPT | 置换最长时间不用的页面（理论最优）|
| FIFO | 置换最早进入的 |
| LRU | 置换最近最久未使用 |
| Clock | LRU 近似，用引用位 |

### 同步机制

1. **互斥锁 Mutex**：二元信号量，一次一个线程
2. **信号量 Semaphore**：计数器，控制并发数
3. **条件变量 Condition Variable**：等待条件成立
4. **读写锁**：读共享，写独占

## 数据库

### 事务 ACID

| 特性 | 含义 |
|------|------|
| 原子性 Atomicity | 全部成功或全部失败 |
| 一致性 Consistency | 事务前后数据完整性一致 |
| 隔离性 Isolation | 并发事务互不干扰 |
| 持久性 Durability | 提交后永久保存 |

### 隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|------|------------|------|
| 读未提交 | 可能 | 可能 | 可能 |
| 读已提交 | 不可能 | 可能 | 可能 |
| 可重复读 | 不可能 | 不可能 | 可能 |
| 串行化 | 不可能 | 不可能 | 不可能 |

**MySQL 默认：可重复读（通过 MVCC + Next-Key Lock 解决幻读）**

### 索引类型

1. **B+ 树索引**：最常用，范围查询友好
2. **哈希索引**：等值查询快，不支持范围
3. **全文索引**：文本搜索

**为什么用 B+ 树不用 B 树？**
- B+ 树非叶子节点不存数据，树更矮，IO 更少
- B+ 树叶子节点用链表连接，范围查询更高效
- B+ 树查询效率稳定（都到叶子节点）

### SQL 调优要点

1. 避免 SELECT *
2. 合理使用索引（避免索引失效）
3. 避免在 WHERE 子句对字段做运算
4. LIKE 查询避免左模糊
5. 大表分页优化（延迟关联）

### MVCC 多版本并发控制

**核心思想**：不直接锁行，而是通过版本号实现读写并发

**实现**：
- 每行记录有隐藏字段：创建版本号、删除版本号
- 读操作：只读创建版本 ≤ 当前版本 且 删除版本为空或 > 当前版本的记录
- 写操作：复制新版本，更新创建版本号

## 其他高频问题

### 设计模式

**单例模式**：确保类只有一个实例
```java
public class Singleton {
    private static volatile Singleton instance;
    private Singleton() {}
    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

**工厂模式**：封装对象创建逻辑
**观察者模式**：发布订阅
**策略模式**：算法可替换

### Redis 常见问题

**数据类型**：String、List、Set、Hash、ZSet

**持久化**：
- RDB：快照，恢复快，可能丢数据
- AOF：日志，数据更安全，文件更大

**缓存穿透**：查询不存在的 key → 布隆过滤器或缓存空值
**缓存击穿**：热点 key 过期 → 加锁重建
**缓存雪崩**：大量 key 同时过期 → 随机过期时间
