MongoDB 提供多种数据加解密方案，主要包括以下几个方面：

1. 传输加密 (Encryption in Transit)

• TLS/SSL 加密：保护数据在客户端与服务器之间、以及集群节点之间的传输安全。

• 默认配置可启用，确保网络传输过程中数据不被窃听。

2. 静态加密 (Encryption at Rest)

a. 原生加密（存储级加密）

• 企业版功能：使用 AES-256-CBC 或 AES-256-GCM 算法加密整个数据文件（WiredTiger 存储引擎级别）。

• 密钥管理：

  • 使用 KMIP：与外部密钥管理服务（如 AWS KMS、HashiCorp Vault 等）集成。

  • 本地密钥管理：使用本地密钥文件（安全性较低，适合测试环境）。

b. 客户端字段级加密 (Client-Side Field Level Encryption, FLE)

• 最细粒度加密：在客户端对特定字段加密后再存储到数据库，服务端无法解密。

• 分类：

  • FLE 1.0（旧版）：需在客户端管理加密密钥。

  • FLE 2.0（推荐）：

    ◦ 支持随机加密（支持等值查询）和确定性加密（支持等值查询、范围查询等）。

    ◦ 密钥由 Key Management Service (KMS) 管理（如 AWS KMS、Azure Key Vault、GCP KMS）。

    ◦ 驱动程序自动处理加解密，对应用透明。

• 适用场景：保护敏感字段（如身份证号、银行卡号等），即使数据库泄露或管理员也无法查看明文。

3. 审计与安全合规

• 企业版：提供审计日志加密、角色访问控制等。

• 字段级加密可结合查询：FLE 2.0 支持对加密字段进行有限查询（如等值匹配）。

4. 注意事项

• 版本与许可证：

  • 静态加密（存储级）和 FLE 2.0 需 MongoDB 企业版 或 Atlas 云服务。

  • Atlas 默认启用传输加密和静态加密，并支持 FLE。

• 性能影响：加密（尤其是客户端字段加密）可能增加 CPU 开销和查询延迟。

• 密钥管理：切勿将加密密钥与数据存储在同一服务器，推荐使用专业 KMS 服务。

5. 推荐方案

• 全链路保护：传输加密（TLS）+ 静态加密（存储级）+ 字段级加密（FLE 2.0）结合。

• 云服务：MongoDB Atlas 已集成多数加密功能，开箱即用。

• 自建部署：企业版可使用 KMIP 或 FLE 实现高安全要求。
