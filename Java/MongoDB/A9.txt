具体说一下 LINEARIZABLE,MAJORITY ,JOURNALED

我来详细解释这三种最严格的 WriteConcern 级别：

1. LINEARIZABLE（线性化）
核心特性

线性化读写：保证读写操作的全局顺序一致性

最强一致性级别：类似于 CPU 内存模型的顺序一致性

MongoDB 4.4+ 支持

@Service
public class FinancialService {
    // 银行转账 - 绝对不能出现不一致
    public void transfer(String from, String to, BigDecimal amount) {
        TransactionOptions txnOptions = TransactionOptions.builder()
            .writeConcern(WriteConcern.LINEARIZABLE)
            .build();
        
        // 保证转账的原子性和一致性
        mongoTemplate.executeTransaction(txnOptions, () -> {
            // 扣款
            mongoTemplate.updateFirst(
                Query.query(Criteria.where("account").is(from)),
                new Update().inc("balance", -amount.doubleValue()),
                Account.class
            );
            
            // 存款
            mongoTemplate.updateFirst(
                Query.query(Criteria.where("account").is(to)),
                new Update().inc("balance", amount.doubleValue()),
                Account.class
            );
            
            return null;
        });
    }
}
2. MAJORITY（多数派）
核心特性

数据持久性保证：写入被复制到大多数节点后才返回

防回滚：一旦被大多数节点确认，即使主节点故障也不会丢失

读取自己的写入：确保后续读取能看到刚写入的数据

    // 4. 返回成功
}

单节点安全性：即使服务器崩溃，数据也不会丢失

恢复能力：可通过日志恢复数据

@Service
public class CriticalDataService {
    
    // 最高安全性：LINEARIZABLE + JOURNALED
    public void saveCriticalData(CriticalData data) {
        // 注意：实际中 LINEARIZABLE 通常隐式包含多数派确认
        // 但可以组合使用获得最高保证
        WriteConcern wc = WriteConcern.MAJORITY
            .withJournal(true)  // 确保日志持久化
            .withWTimeout(15, TimeUnit.SECONDS);
        
        // 在事务中使用
        TransactionOptions options = TransactionOptions.builder()
            .writeConcern(wc)
            .maxCommitTime(10, TimeUnit.SECONDS)
            .build();
        
        mongoTemplate.executeTransaction(options, () -> {
            // 多个相关操作
            mongoTemplate.save(data);
            mongoTemplate.save(new AuditLog("Data saved", data.getId()));
            return null;
        });
    }
    
    // 不同场景的选择
    public void processData(Data data, DataImportance importance) {
        WriteConcern wc;
        
        switch (importance) {
            case CRITICAL:
                // 金融数据：线性化保证
                wc = WriteConcern.LINEARIZABLE
                    .withWTimeout(10, TimeUnit.SECONDS);
                break;
                
            case IMPORTANT:
                // 订单数据：多数派保证
                wc = WriteConcern.MAJORITY
                    .withWTimeout(5, TimeUnit.SECONDS)
                    .withJournal(false);
                break;
                
            case AUDIT:
                // 审计日志：日志持久化
                wc = WriteConcern.JOURNALED
                    .withWTimeout(3, TimeUnit.SECONDS);
                break;
                
            default:
                // 普通数据：默认确认
                wc = WriteConcern.ACKNOWLEDGED;
        }
        
        mongoTemplate.save(data, wc);
    }
}

@Component
public class WriteConcernMonitor {
    
    @Autowired
    private MongoTemplate mongoTemplate;
    
    // 监控写入延迟
    public void monitorWritePerformance() {
        // 记录不同 WriteConcern 的性能
        Map<WriteConcern, Long> latencies = new HashMap<>();
        
        WriteConcern[] concerns = {
            WriteConcern.UNACKNOWLEDGED,
            WriteConcern.ACKNOWLEDGED,
            WriteConcern.JOURNALED,
            WriteConcern.MAJORITY
        };
        
        for (WriteConcern wc : concerns) {
            long start = System.currentTimeMillis();
            
            try {
                TestData data = new TestData("test", new Date());
                mongoTemplate.save(data, wc);
                
                long latency = System.currentTimeMillis() - start;
                latencies.put(wc, latency);
                
                logger.info("WriteConcern {} latency: {}ms", 
                    wc.getWString(), latency);
                    
            } catch (MongoTimeoutException e) {
                logger.warn("WriteConcern {} timeout", wc.getWString());
            }
        }
        
        return latencies;
    }
    
    // 动态调整 WriteConcern
    public WriteConcern getDynamicWriteConcern(boolean isPeakHour) {
        if (isPeakHour) {
            // 高峰时段：降低一致性要求，提高吞吐量
            return WriteConcern.W1
                .withWTimeout(2, TimeUnit.SECONDS)
                .withJournal(false);
        } else {
            // 非高峰时段：使用更高的一致性
            return WriteConcern.MAJORITY
                .withWTimeout(5, TimeUnit.SECONDS);
        }
    }
}
6. 最佳实践总结

LINEARIZABLE：

用于需要最强一致性的场景

注意：性能开销最大，可能产生更高的延迟

通常与多文档事务一起使用

MAJORITY：

业务关键数据的默认选择

平衡了安全性和性能

配合合适的超时设置避免长时间阻塞

JOURNALED：

当单节点持久性比复制更重要时使用

确保服务器崩溃时数据不丢失

注意：需要启用 MongoDB 的 journal 功能

重要建议：

总是设置合理的超时（wtimeout）

监控不同 WriteConcern 的实际性能

根据业务重要性分级使用

考虑复制集节点数量和网络延迟

在事务中谨慎使用高级别 WriteConcern

MAJORITY 中提到的 大多数节点，到底是多少个节点。如果有些节点还没有写入或确认，读数据的时候会出现数据不一致的情况吗

3.1 ReadConcern 与 WriteConcern 的组合

@Service
public class ConsistencyService {
    
    public enum ConsistencyLevel {
        EVENTUAL,      // 最终一致性
        MAJORITY,      // 多数派一致性
        LINEARIZABLE   // 线性一致性
    }
    
    public void writeWithConsistencyLevel(ConsistencyLevel level, Object data) {
        WriteConcern wc;
        
        switch (level) {
            case LINEARIZABLE:
                wc = WriteConcern.MAJORITY.withJournal(false);
                // 注意：实际生产中，线性化通常需要特殊处理
                break;
            case MAJORITY:
                wc = WriteConcern.MAJORITY.withWTimeout(5, TimeUnit.SECONDS);
                break;
            case EVENTUAL:
            default:
                wc = WriteConcern.W1;  // 只需要主节点确认
        }
        
        mongoTemplate.save(data, wc);
    }
    
    public Object readWithConsistencyLevel(ConsistencyLevel level, String id) {
        MongoCollection<Document> collection = mongoTemplate.getCollection("data");
        
        switch (level) {
            case LINEARIZABLE:
                // 线性化读取
                collection = collection
                    .withReadConcern(ReadConcern.LINEARIZABLE)
                    .withReadPreference(ReadPreference.primary());
                break;
            case MAJORITY:
                // 读取已提交到多数节点的数据
                collection = collection
                    .withReadConcern(ReadConcern.MAJORITY)
                    .withReadPreference(ReadPreference.primaryPreferred());
                break;
            case EVENTUAL:
            default:
                // 最终一致性读取
                collection = collection
                    .withReadConcern(ReadConcern.LOCAL)
                    .withReadPreference(ReadPreference.nearest());
        }
        
        return collection.find(new Document("_id", id)).first();
    }
}

4.2 处理读取延迟的实用方法
java

@Service
public class DataService {
    
    @Autowired
    private MongoTemplate mongoTemplate;
    
    /**
     * 强一致性读取：确保读取到自己的写入
     */
    public <T> T readAfterWrite(String id, Class<T> entityClass, 
                              Supplier<T> writeOperation) {
        // 执行写入
        T writtenData = writeOperation.get();
        
        // 尝试读取，最多重试3次
        for (int i = 0; i < 3; i++) {
            T readData = mongoTemplate.findById(id, entityClass);
            if (readData != null) {
                return readData;
            }
            
            try {
                Thread.sleep(100 * (i + 1));  // 递增等待
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                break;
            }
        }
        
        // 最后尝试从主节点读取
        MongoCollection<Document> collection = mongoTemplate
            .getCollection(mongoTemplate.getCollectionName(entityClass))
            .withReadPreference(ReadPreference.primary());
        
        Document doc = collection.find(new Document("_id", id)).first();
        return doc != null ? mongoTemplate.getConverter().read(entityClass, doc) : null;
    }
    
    /**
     * 使用因果一致性会话
     */
    public void causalConsistencyExample() {
        ClientSession session = mongoTemplate.getDb().getClient().startSession();
        
        try {
            session.startTransaction(TransactionOptions.builder()
                .readConcern(ReadConcern.SNAPSHOT)
                .writeConcern(WriteConcern.MAJORITY)
                .build());
            
            // 操作1：写入
            mongoTemplate.save(new User("1", "Alice"), session);
            
            // 操作2：读取 - 保证能看到操作1的写入
            User user = mongoTemplate.findById("1", User.class, session);
            
            session.commitTransaction();
            
        } finally {
            session.close();
        }
    }
}

5.1 MAJORITY 的具体节点数

3节点集群：需要2个节点确认

保证了：即使主节点故障，写入的数据也不会丢失

5.3 最佳实践建议

写入时：关键数据使用 writeConcern: "majority"

读取时：需要强一致性时使用 readConcern: "majority"

组合使用：writeConcern: "majority"+ readConcern: "majority"保证读写一致性

超时设置：合理设置 wtimeout避免长时间阻塞

监控：监控复制延迟和节点状态
